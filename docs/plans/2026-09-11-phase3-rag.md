# RepoView Phase 3 (RAG) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 키워드 검색(`search_code`)으로 못 찾는 개념적 질문에 답할 수 있도록, 코드를 청크로 나눠 임베딩하고 의미 검색(`search_semantic`)으로 에이전트에 연결한다.

**Architecture:** 기존 Repo Indexer와 분리된 새 컴포넌트 Embedder(`python -m repoview.embed`)가 `iter_code_files`(Phase 2에서 이미 구현됨)로 얻은 파일을 50줄 슬라이딩 윈도우로 청킹하고, OpenAI 임베딩 API로 벡터화해 Chroma에 저장한다. 에이전트 루프(`run_session`)는 `embedding_client`를 주입받아 세션 시작 시 해당 레포의 Chroma 컬렉션을 찾고, `search_semantic` 도구 호출을 그 컬렉션에 위임한다. 임베딩이 아직 없는 레포는 `search_semantic`이 명확한 에러 메시지로 안내한다(크래시 없음).

**Tech Stack:** 기존 스택(Python 3.12, FastAPI, sqlite3, openai SDK, pytest) + `chromadb`(신규). 이 계획을 작성하며 `chromadb==1.5.9`와 `openai` SDK의 임베딩 API를 실제로 설치·호출해 시그니처를 검증했다 — 아래 코드는 추측이 아니라 확인된 API다.

**Spec:** `docs/01-prd.md`, `docs/02-architecture.md`(4절), `docs/03-db-design.md`(4절), `docs/05-agent-design.md`(검색 전략 안내 절)

## Global Constraints

- Phase 1+2의 모든 제약(Python 3.12+, ORM 미사용, 도구는 `"ERROR: ..."` 문자열로 실패 반환, 한국어 커밋 메시지)이 그대로 적용된다.
- 신규 의존성은 `chromadb`만 추가한다. 임베딩 모델은 OpenAI `text-embedding-3-small`.
- **모든 자동화 테스트는 `FakeEmbeddingClient`를 사용하므로 실제 OpenAI API 키 없이도 전부 통과해야 한다** (Phase 1+2의 `FakeLLM` 제약과 동일한 원칙).
- Chroma 데이터 디렉토리(`chroma_data/`)는 `.gitignore`에 추가한다 — `repoview.db`와 동일하게 로컬 생성물이다.
- 청킹 대상 파일 집합은 반드시 기존 `iter_code_files`(`repoview/tools/search.py`)를 재사용한다. 새로 파일 순회 로직을 만들지 않는다.
- 기존 `dispatch(repo_root, name, args)`의 3개 도구(list_directory/read_file/search_code) 호출부는 이 계획으로 인해 동작이 바뀌면 안 된다 — `collection`/`embedding_client`는 반드시 키워드 전용 인자로 추가한다.
- `run_session`에 새로 추가하는 `embedding_client` 파라미터는 기본값 `None`을 가져야 한다 — 기존 `tests/test_agent_loop.py`의 모든 테스트가 이 파라미터 없이 호출되므로, 하위 호환이 깨지면 안 된다.

## 이 계획에서 다루지 않는 것

- **Eval Runner** (`python -m repoview.eval`, `eval_case`/`eval_run`/`eval_result` 테이블 활용): PRD의 "Phase 2→3 탐지율 비교"에 필요하지만, eval 셋 20~30개 작성과 LLM-as-judge 채점 파이프라인은 그 자체로 독립적인 작업량이다. 이 RAG 구현이 끝난 뒤 별도 계획으로 진행한다.
- 프론트엔드 변경 없음 — `search_semantic`은 기존 `POST /api/sessions` 흐름 안에서 투명하게 동작하므로 API 응답 형태가 바뀌지 않는다.

```python
from pathlib import Path

from repoview.config import CHUNK_LINES, CHUNK_OVERLAP
from repoview.tools.search import iter_code_files


def chunk_file(path: Path, root: Path) -> list[dict]:
    text = path.read_text(encoding="utf-8", errors="replace")
    lines = text.splitlines()
    if not lines:
        return []

    relative_path = path.relative_to(root).as_posix()
    step = CHUNK_LINES - CHUNK_OVERLAP

    chunks: list[dict] = []
    start = 0
    while True:
        end = min(start + CHUNK_LINES, len(lines))
        chunks.append(
            {
                "text": "\n".join(lines[start:end]),
                "file_path": relative_path,
                "start_line": start + 1,
                "end_line": end,
            }
        )
        if end >= len(lines):
            break
        start += step

    return chunks


def chunk_repo(root: Path) -> list[dict]:
    root = Path(root)
    chunks: list[dict] = []
    for path in iter_code_files(root):
        try:
            chunks.extend(chunk_file(path, root))
        except OSError:
            continue
    return chunks


def collection_name(repo_name: str) -> str:
    return f"repo_{repo_name.lower()}"
```

> `collection_name`은 이번 태스크에서 아직 테스트하지 않는다 — Task 5(임베딩 오케스트레이션)와 Task 7(에이전트 루프 연동)이 같은 함수를 각각 쓰기(write)/읽기(read) 방향으로 사용해야 이름 규칙이 어긋나지 않으므로, 여기 미리 정의해 둔다.

```python
import hashlib

from repoview.config import EMBEDDING_MODEL


class OpenAIEmbeddingClient:
    def __init__(self, model: str = EMBEDDING_MODEL) -> None:
        from openai import OpenAI

        self.model = model
        self._client = OpenAI()

    def embed(self, texts: list[str]) -> list[list[float]]:
        response = self._client.embeddings.create(input=texts, model=self.model)
        return [item.embedding for item in response.data]


class FakeEmbeddingClient:
    """테스트용. 텍스트의 SHA-256 해시에서 뽑은 결정론적 벡터를 반환한다.

    같은 텍스트는 항상 같은 벡터를 반환하므로, 정확히 일치하는 텍스트를
    쿼리했을 때 그 청크가 최상위 결과로 나오는지 검증하는 용도로 충분하다.
    실제 의미적 유사도는 검증하지 않는다 — 그건 eval의 역할이다.
    """

    def __init__(self, dim: int = 8) -> None:
        self.dim = dim
        self.embed_calls: list[list[str]] = []

    def embed(self, texts: list[str]) -> list[list[float]]:
        self.embed_calls.append(list(texts))
        return [self._vector_for(text) for text in texts]

    def _vector_for(self, text: str) -> list[float]:
        digest = hashlib.sha256(text.encode("utf-8")).digest()
        return [digest[i] / 255.0 for i in range(self.dim)]
```

`repoview/tools/semantic.py`:

```python
from repoview.config import DEFAULT_TOP_K
from repoview.tools.search import MAX_LINE_PREVIEW


def search_semantic(collection, embedding_client, query: str, top_k: int | None = None) -> str:
    if collection is None:
        return (
            "ERROR: 이 레포는 아직 임베딩되지 않았습니다. "
            "python -m repoview.embed로 먼저 임베딩하세요."
        )

    limit = top_k if top_k is not None else DEFAULT_TOP_K

    try:
        query_embedding = embedding_client.embed([query])[0]
    except Exception as exc:
        return f"ERROR: 임베딩 생성 실패: {exc}"

    results = collection.query(query_embeddings=[query_embedding], n_results=limit)

    ids = results["ids"][0]
    if not ids:
        return "일치하는 결과가 없습니다."

    lines = []
    for metadata, document in zip(results["metadatas"][0], results["documents"][0]):
        first_line = document.splitlines()[0] if document else ""
        snippet = first_line.strip()[:MAX_LINE_PREVIEW]
        lines.append(f"{metadata['file_path']}:{metadata['start_line']}-{metadata['end_line']}: {snippet}")

    return "\n".join(lines)

def embed_repo(
    conn,
    repo_id: int,
    name: str,
    root: Path,
    embedding_client,
    chroma_path: Path,
) -> dict:
    chunks = chunk_repo(Path(root))

    client = chromadb.PersistentClient(path=str(chroma_path))
    name_in_chroma = collection_name(name)
    try:
        client.delete_collection(name=name_in_chroma)
    except NotFoundError:
        pass
    collection = client.create_collection(name=name_in_chroma)

    for batch in _batched(chunks, EMBED_BATCH_SIZE):
        texts = [chunk["text"] for chunk in batch]
        embeddings = embedding_client.embed(texts)
        collection.add(
            ids=[f"{c['file_path']}:{c['start_line']}-{c['end_line']}" for c in batch],
            documents=texts,
            metadatas=[
                {"file_path": c["file_path"], "start_line": c["start_line"], "end_line": c["end_line"]}
                for c in batch
            ],
            embeddings=embeddings,
        )

    conn.execute("UPDATE repo SET chunk_count = ? WHERE id = ?", (len(chunks), repo_id))
    conn.commit()

    return {"repo_id": repo_id, "chunk_count": len(chunks)}


def _batched(items: list, size: int):
    for start in range(0, len(items), size):
        yield items[start : start + size]
```

def dispatch(
    repo_root: Path,
    name: str,
    args: dict,
    *,
    collection=None,
    embedding_client=None,
) -> str:
    """도구를 실행한다. 어떤 실패도 예외로 전파하지 않고 'ERROR: ...' 문자열로 반환한다."""
    try:
        if name == "list_directory":
            return list_directory(repo_root, args.get("path", ""))
        if name == "read_file":
            return read_file(
                repo_root,
                args["path"],
                _optional_int(args.get("start_line")),
                _optional_int(args.get("end_line")),
            )
        if name == "search_code":
            return search_code(
                repo_root,
                args["pattern"],
                args.get("path_glob"),
                _optional_int(args.get("max_results")),
            )
        if name == "search_semantic":
            return search_semantic(
                collection,
                embedding_client,
                args["query"],
                _optional_int(args.get("top_k")),
            )
        return f"ERROR: 알 수 없는 도구입니다: {name}"
    except KeyError as exc:
        return f"ERROR: 필수 인자가 없습니다: {exc}"
    except (TypeError, ValueError) as exc:
        return f"ERROR: 인자가 올바르지 않습니다: {exc}"
    except Exception as exc:  # 도구 실패가 루프를 중단시키면 안 된다
        return f"ERROR: 도구 실행 실패: {exc}"
