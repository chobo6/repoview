# PRD — RepoView

## 1. 개요

LocalQuest(Java/Spring)와 Songpyeon(Node/TS) 두 개인 프로젝트를 대상으로, 자연어 질문("성능 문제 찾아줘" 등)에 대해 AI 에이전트가 스스로 레포 구조 탐색 → 관련 코드 검색 → 파일 읽기 → 분석 → 필요시 추가 검색을 반복하며 근거 기반 코드 리뷰를 작성해주는 웹 애플리케이션이다. AI 스타트업 지원용 포트폴리오 프로젝트로 진행한다.

## 2. 범위 (Phase 1~4, 전부 이 PRD에 포함)

- **Phase 1 — Repository 분석**: 레포 구조 파악(디렉토리 트리, 언어/프레임워크 감지)
- **Phase 2 — 코드 리뷰**: 정적 검색(grep류) 기반으로 자유 질문에 답하는 기본 리뷰 기능
- **Phase 3 — RAG 추가**: 키워드 검색의 한계를 보완하는 임베딩 기반 의미 검색
- **Phase 4 — Agent 핵심 기능**: OpenAI function calling 기반 자율 루프(검색 → 판단 → 추가 검색 → 최종 리뷰), 프레임워크 없이 직접 구현
  - **용어 안내 (사후 기록)**: 이 자율 루프는 실제로는 Phase 3(RAG) 구현과 함께 완성되어 별도 실행 모드 없이 `config.CURRENT_PHASE = 3`으로 합쳐졌다. 이후 안전장치(반복 호출 감지·토큰 상한·인용 사후검증)를 추가하는 작업 라운드가 "Phase 4"라는 이름을 재사용했는데, 이 절의 원래 정의와는 다른 작업이다 — 코드/eval에서 실제로 쓰이는 `phase` 값은 여전히 2와 3뿐이다. 자세한 경위는 `docs/06-test-eval-design.md`의 "판단 이유" 참고.

## 3. 대상/제약

- 대상 레포: LocalQuest, Songpyeon 2개로 고정 (로컬에 이미 클론돼 있음, GitHub API로 임의 레포를 받는 기능은 없음)
- 인터페이스: 웹 앱, 로컬 실행 전용 (배포하지 않음)
- 백엔드: Python
- LLM: OpenAI API
- 질문 방식: 자유 자연어 질문형 (카테고리 버튼 없음)

## 4. 비목표 (Out of scope)

- 임의 공개 GitHub repo 지원 (범용 SaaS 아님)
- 실제 클라우드 배포
- 코드 자동 수정/자동 PR 생성
- LocalQuest·Songpyeon 외 언어/프레임워크 지원

## 5. 성공 기준

- **정성**: "성능 문제 찾아줘" 등 자유 질문에 파일:라인 근거를 포함한 리뷰를 생성한다.
- **정량**: 두 레포에 의도적으로 심어둔 버그(N+1 쿼리, 이미 알고 있는 실제 트러블슈팅 사례 등)로 eval 셋을 만들어 Phase별 탐지율을 측정한다. Phase 2(정적 검색만) → Phase 3(+RAG)로 갈수록 탐지율이 개선되는 것을 숫자로 보여주는 것이 핵심 데모 포인트다 — 실제로 돌려본 결과, 수치상 Phase 3이 평균적으로 높긴 하지만 재실행마다의 변동폭과 비슷한 수준이라 통계적으로 유의미하다고 단정하긴 이르다는 게 현재까지의 정직한 결론이다(`docs/TROUBLESHOOTING.md` 참고).
- **면접 데모**: 실제 질문 3~5개 시나리오를 스크립트로 준비해 라이브 데모가 가능해야 한다.

## 6. 주요 리스크

- 에이전트 루프가 종료 조건 없이 반복될 경우 OpenAI API 비용이 급증할 수 있다 → 최대 반복 횟수 하드캡이 필요하다 (아키텍처 설계 단계에서 구체화).
- 두 레포의 언어(Java vs Node/TS)가 달라 코드 검색/파싱 로직이 언어별로 분기될 수 있다.
